# 요청 기록하기

사용자는 할 일을 옵시디안에 번호를 붙여 적어 두고 일을 시킨다. 대화창에 바로 요청해도
**그 노트에 사용자가 적은 것처럼 남아야** 나중에 한 곳에서 본다. 그래서 요청을 받으면 먼저 기록하고, 끝내면 결과 줄을 단다.

## 경로와 노트

볼트: `C:\Users\ocean\Documents\mv\Project\fd2-remake\` — 옵시디안 MCP 가 안 붙어 있어도 이 폴더의 `.md` 를 Read·Edit 로 바로 고친다.

| 요청이 어디 것인가 | 노트 | 번호 머리 |
|---|---|---|
| 게임·개발도구의 기능, 버그, 수치, 화면 | `작업\작업.md` | `w-` |
| 만든 것에 대한 고침(「이건 이렇게 돼야 해」, 기본값·동작·모양 바로잡기) | `작업\피드백.md` | `fb-` |
| 원본 분석 부탁(「이거 분석해 봐」) | `작업\작업.md` 에 적고, 결과는 `분석\분석-….md` 로 | `w-` |

`작업` 폴더는 매번 새로 훑는다 — 사용자가 노트를 나누거나 새로 만들 수 있다. 주제별 노트가 생기면 그 노트의 머리를 따른다.
분석 노트는 `분석\` 에 있다(분석-장면 · 분석-명령메뉴 …). 사용자가 적은 줄은 고치지 않는다.

## 기록하는 꼴

사용자가 쓰는 꼴 그대로다 — 빈 줄 하나, 번호 한 줄, 요청 글(사용자가 입력한 말을 **거의 그대로**, 오타만 고치고 말투는 둔다).

```
w-5
커스텀설정 조선 만들어 줘 재질 고르고 적재 변경도
```

- 번호 = 그 노트에서 **같은 머리의 가장 큰 번호 + 1**. 겹치지 않게 가장 큰 것을 센다.
- 한 번에 여러 요청이면 요청마다 번호를 따로 준다. 한 요청 안의 곁가지("그리고 ~도")는 같은 번호에 줄을 더한다.
- 스크린샷이나 링크가 붙은 요청은 무엇을 가리키는지 글로 한 줄 덧붙인다(「사진: 원본 선박 구입 창」, 「링크: 인벤 조선 풀이 글」).
- 기록은 요청을 받은 **바로 그때**, 일을 시작하기 전에 한다. 사용자의 줄은 고치거나 순서를 바꾸지 않는다.

## 끝냈을 때

그 번호 밑에 인용 줄로 결과를 붙인다(이 노트에서 이미 쓰는 꼴).

```
> w-5 했음(2026-10-05) — 무엇을 어디에 어떻게. 확인한 것과 못 한 것. 커밋 abc1234
```

- 분석 부탁이면 `> w-N 분석함(날짜) — [[65.분석-…]] 한 줄 결론`.
- 코드 없이 답만 한 요청은 `> w-N 답(날짜) — …`.
- 사용자가 고르기를 기다리는 것이면 `> w-N 대기 — 무엇을 골라야 하는지`. 다음에 다시 이어 간다.
- 일부만 됐으면 `> w-N 일부(날짜) — 된 것 / 안 된 것과 까닭`.
- 화면으로 확인 못 한 것, 지어낸 수치, 원본과 다를 수 있는 것은 그렇다고 적는다.
- 커밋은 사용자가 말할 때만 하므로, 아직 커밋 전이면 커밋 번호 대신 「커밋 전」이라고 적고 커밋한 뒤 고친다.

## 기록하지 않는 것

- 질문만 하고 바꿀 것이 없는 말("이거 원본이 이런 거냐")은 답만 한다 — 다만 답 끝에 할 일이 생기면 그때 기록한다.
- "커밋 앤 푸쉬", "계속 해", "응" 같은 확인·지시, 이 스킬 자체에 대한 요청.
